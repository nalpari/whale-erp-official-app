# My Commit - 클린 커밋 커맨드

아래 단계를 **순서대로** 실행하세요.

## 1단계: 커밋 대상 파일 확인

`git diff --cached --name-only`와 `git diff --name-only`를 실행하여 staged + unstaged 변경 파일 목록을 확인합니다.
변경된 파일이 없으면 사용자에게 알리고 중단합니다.

## 2단계: 파일 타입별 미사용 코드 스캔 및 제거

변경된 파일을 읽고, 파일 타입에 따라 다음을 검사합니다:

### Kotlin (.kt) 파일:
- **미사용 import**: import된 클래스/함수가 파일 본문에서 사용되지 않는 경우 제거
- **미사용 변수**: 선언된 `val`/`var` 중 이후 코드에서 참조되지 않는 경우 제거
- **미사용 파라미터**: private 함수의 파라미터 중 함수 본문에서 사용되지 않는 경우 `_` prefix 추가 또는 제거 검토

### TypeScript/JavaScript (.ts, .tsx, .js, .jsx) 파일:
- **미사용 import**: import된 모듈/변수가 파일에서 사용되지 않는 경우 제거
- **미사용 변수**: `const`, `let`, `var`로 선언된 변수 중 참조되지 않는 경우 제거

### 공통 규칙:
- **주석 처리된 코드 블록**: 5줄 이상의 연속 주석 처리된 코드가 있으면 사용자에게 알림
- **빈 import 문**: import 후 아무것도 가져오지 않는 문장 제거 (예: `import {} from '...'`)

## 3단계: 변경사항 리포트

제거한 항목을 파일별로 요약하여 사용자에게 보여줍니다:
```
[파일명]
  - 제거된 import: xxx, yyy
  - 제거된 변수: zzz
```

변경사항이 없으면 "클린 코드입니다! 미사용 코드가 없습니다." 라고 알립니다.

## 4단계: 파일 스테이징 및 커밋

1. 변경된 모든 파일을 `git add`로 스테이징합니다 (파일명을 명시적으로 지정).
2. 커밋 메시지를 다음 형식으로 작성합니다:
   - 변경 내용을 분석하여 적절한 prefix 사용 (`feat:`, `fix:`, `refactor:`, `chore:` 등)
   - 미사용 코드 제거가 포함된 경우 커밋 메시지에 "clean up unused code" 내용 추가
   - Co-Authored-By 헤더 포함
3. 커밋을 생성합니다.

## 주의사항

- **절대로** 테스트 파일의 미사용 변수는 제거하지 마세요 (테스트 픽스처일 수 있음)
- **절대로** `@Suppress("unused")` 어노테이션이 있는 Kotlin 코드는 건드리지 마세요
- **절대로** `// eslint-disable-next-line no-unused-vars` 주석이 있는 JS/TS 코드는 건드리지 마세요
- **절대로** export된 변수/함수는 제거하지 마세요 (다른 파일에서 사용될 수 있음)
- Entity, DTO, Config 클래스의 필드는 프레임워크가 사용하므로 제거하지 마세요
- 의심스러운 경우 제거하지 않고 사용자에게 확인을 요청하세요
- **절대로** `CLAUDE.md`, `AGENTS.md` 파일은 커밋에 포함하지 마세요
